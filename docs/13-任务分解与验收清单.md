# Symweft 任务分解与验收清单

更新日期：2026-10-19。此文是后续逐项推进和标记完成的统一入口；[总体设计](01-产品与技术设计.md) 描述目标，[开发记录](03-开发记录.md) 保留过程和历史数据。

## 1. 使用与更新规则

- `[x]`：在该条写明的范围内已经实现，并有代码、测试或实测记录支持。
- `[ ]`：尚未达到验收条件；有原型、接口或设计也保持未勾选。开始实施时可追加“进行中”，缺少环境时写明“待实机验证”及原因。
- 每项保留固定编号，例如 `OVL-02`。后续可以直接按编号指定工作；需要继续拆分时追加子任务，不重排旧编号。
- 每项必须具备可观察的验收结果。完成后同时更新勾选、证据和必要的能力说明；协议改变更新 04，用户可见能力改变更新 README，工作过程记入 03。
- 已完成仅适用于当前公开范围和验证平台。A1 语法不等于 A2 语义；单 TU 不等于全项目；macOS 通过不等于 Linux/Windows 通过；后端接口通过不等于 UI 已接通。
- 修改事实、缓存或调度后执行相关回归；文档变更只检查清单、依赖和链接。未改变实现时不重复执行整套大型基准。
- 下表计数由本文件任务勾选统计。任务大小不同，**勾选数量不代表产品完成百分比**。不把设计文档、32 项测试或 QEMU 子集通过当作完整产品验收。
- 当前没有额外的后台执行安排；本文件用于后续工作回合选择任务，不代表其中未完成任务已经启动。

术语：TU 为 C/C++ 编译单元；overlay 为未保存内容产生的内存语义事实；preamble 为可复用的头部解析结果。近期任务按可提交和可验收的能力拆分；进入远期模块时，若单项仍过大，先追加更小子任务。
