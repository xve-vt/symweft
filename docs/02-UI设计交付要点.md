# Symweft：UI 设计交付要点

版本：v0.4 分析与关系交互优先  
日期：2026-10-18  
用途：直接作为 Claude Design、Google Stitch 或专业设计师的设计输入。输出高保真桌面界面、组件、状态与可点击原型即可，本阶段无需输出业务实现代码。

完整产品定义见：[产品与技术设计](01-产品与技术设计.md)。本文件中的工程、代码、计数和资源数值都是统一演示数据，不是产品实测。

已确认（最新）：**当前从 macOS 本机开始实现，Linux/GNOME 后续重点支持，Windows 更后。主题默认跟随系统、实时响应变化；原设计稿颜色太深，必须提亮，浅色和深色同等完整。**先设计 macOS 原生工作台，各平台共享任务语义并保留原生交互。

最新设计侧重：**分析是产品核心**。阅读工作台优先呈现当前符号、大纲、入/出调用与证据；关系随光标和修订更新，后台索引不遮挡已可用内容。语法调用点与已解析调用目标明确区分；提供范围、过期/候选状态及可取消任务，不用永久旋转进度表达全库分析。性能和资源数值来自运行测量，不放固定演示数字作为承诺。当前原型的文件大纲/调用点不是完整语义图，详见 [引擎设计](05-分析引擎与实时关系设计.md)。

## 1. 产品与设计目标

### 最新 C/C++ 语义面板设计输入

实时更新补充：增加自动更新已索引范围、严格内容校验和强制刷新已索引范围；区分用户暂停、内存压力暂停、配置变化、监听降级与自动预算超限。只读阅读器响应外部保存，未来可编辑模式必须提供冲突处理。具体状态与交互见 [实时更新设计](11-实时语义更新与查询优化.md#5-协议与-ui)。

- 入口：原生“导入编译配置”；展示目标/编译单元覆盖范围，导入不等于全库已分析。
- 任务：分析当前文件、进度、取消、失败诊断与重试；保持源码可读，不使用全屏等待。
- 光标上下文：当前符号、定位定义、出调用/入调用；点击打开调用点，菜单可定位目标定义。默认使用真实关系，不混入语法候选。
- 证据状态：直接绑定、虚调用候选、函数指针目标未知、未解析、过期、未索引；调用类型需有文字标签，不能只靠颜色。
- 头文件或多命令：选择编译单元/构建变体，明确所属主文件、目标与宏配置，避免多个分支混成确定关系。
- 大结果：分页/更多结果、显示数量与查询上限、覆盖范围；区分“没有关系”和“尚未索引”。当前原型最多请求 100 项、先显示 30 项，后续设计补足分页。
- 未保存内容：未来提供缓冲区修订与预览状态；编译出错仍允许语法阅读，旧语义不能冒充当前结果。
- 系统主题：上述新面板必须与窗口实时同步浅色/深色；使用原生语义颜色、中性代码背景，避免恢复初稿的深蓝黑色。

工程实现与测量不作为视觉演示数字写死，见 [C/C++ 报告](10-C-Cpp语义闭环与QEMU验证.md)。

**一句话**：为 Python、C/C++、Rust、Java 开发者设计一款以代码理解为中心的跨平台桌面 IDE，让源码、调用关系、控制流与多仓库架构在一个连续工作台中联动。

必须突出五点：

- 深度代码阅读：上下文、调用方/被调用方、定义/引用与阅读历史。
- 图谱能力：调用图、函数流程图、分层架构、依赖矩阵与影响范围。
- 跨项目：一个工作空间里联合浏览多个仓库和多种语言，清楚显示 RPC/FFI 边界。
- 可信分析：确定、候选、未知、运行时观测、人工映射与过期状态能辨识，关系有证据。
- 轻量流畅：后台任务可控制；常用操作直接；静止时克制，适合长期编码与阅读。

视觉关键词：**精密、沉静、紧凑、层级清晰、长时间使用舒适、信息密度高但可逐层展开**。

参考工作方式：Source Insight 的上下文阅读与关系联动、Understand 的分析视图、现代 IDE 的编辑与工具面板。建立独立的界面语言和图谱设计，不复制品牌、图标或完整布局。

## 2. 设计交付范围

先以 macOS 为目标验证阅读工作台和系统主题，再补齐以下 12 个画面；GNOME 与 Windows 后续分别进行原生设计：

| 页面 | 优先级 | 应证明的体验 |
|---|---|---|
| 01 阅读工作台 | P0 | 代码、结构、调用概览联动 |
| 02 调用图工作台 | P0 | 局部关系展开、证据、返回源码 |
| 03 函数控制流 | P0 | 代码与分支/循环/异常同步 |
| 04 跨项目系统地图 | P0 | 仓库、语言、契约、FFI 的分层关系 |
| 05 关系证据检查器 | P0 | 用户能判断一条边依据什么成立 |
| 06 项目导入与分析状态 | P0 | 缺少环境仍可开始阅读 |
| 07 资源与后台任务 | P0 | 能看见并控制成本 |
| 08 搜索与命令面板 | P0 | 高频键盘操作、结果预览 |
| 09 开发/调试工作台 | P1 | IDE 工具出现时阅读体验仍连续 |
| 10 变更影响 | P1 | 潜在影响、路径、建议测试 |
| 11 架构规则与 DSM | P1 | 发现循环、违规、依赖边界 |
| 12 快照对比与阅读路径 | P1 | 架构变化与阅读成果可复查 |

同一平台内，页面可以是该平台 shell 的不同布局状态。先完成 macOS 的 01、02、04、05、07，再扩展其他画面。跨平台共享任务、信息含义、命令与图谱图例；分别维护 GNOME、macOS、Windows 组件映射，不通过只替换标题栏交付原生设计。

### 2.1 原生体验合同

| 目标 | 平台设计重点 | 验收要点 |
|---|---|---|
| Linux / GNOME、Ubuntu 默认桌面 | GTK4/libadwaita 的工作台、header bar、侧栏、动作与对话框；参考成熟 GNOME 开发工具的信息密度 | Wayland、IBus/Fcitx、AT-SPI、系统主题/缩放、文件门户、窗口按钮习惯 |
| macOS | AppKit 主工作台、适合区域使用 SwiftUI；系统菜单、toolbar、sidebar、inspector 与独立窗口 | Cmd 快捷键、触控板、VoiceOver、IME、原生文件面板与窗口行为 |
| Windows | WinUI/Win32 工作台，Fluent 控件语义、标题栏与命令组织 | Ctrl 快捷键、TSF、UIA、高对比度、混合 DPI、窗口与文件操作 |

原生体验包含可用性和行为，不等同于套用默认大间距。保持 IDE 所需的紧凑密度与持久工具面板。代码/图谱可以专业自绘，但输入、焦点、上下文菜单和可访问语义必须符合平台。

Linux 当前只把 GNOME/Ubuntu 作为原生设计主目标。KDE 首期要求功能兼容，不把 Adwaita 界面描述成 KDE 原生设计；未来若需要 KDE 同级体验，单独建立设计分支。

## 3. 窗口结构与尺寸

### 3.1 主画板

- 主设计尺寸：1600 × 1000；补充 1440 × 900 与 1280 × 800 的重排验证；先完成 macOS。
- 三个平台共用核心信息与任务，分别设计原生窗口、命令入口、面板、菜单与快捷键；尺寸 token 允许因平台调整。
- Linux/GNOME：以 GTK4/libadwaita 工作台为基础，header bar、窗口按钮、侧栏、popover 与文件面板遵循 GNOME；不要沿用 macOS 系统菜单条或 Windows 标题栏。
- macOS：使用系统菜单、原生 toolbar/sidebar/inspector；系统窗口按钮留出安全区，支持平台自然的多窗口行为。
- Windows：按 WinUI/Win32 和 Fluent 组织窗口与命令，保留系统窗口操作与键盘路径。
- 桌面窗口可以自由调整，不需要手机页面。

### 3.2 常规布局

```text
┌──────────────── 项目 / 工作空间 / 搜索 / 模式 ────────────────┐
│活动栏│项目、符号、阅读路径│源码标签 / 图谱标签       │检查器  │
│      │                 │                         │        │
│      │                 │源码 ⇄ 图谱（按需分屏）   │证据/属性│
│      │                 │                         │        │
│      │                 ├──────── 底部工具区 ───────────────┤
│      │                 │问题 / 终端 / 测试 / 输出 / Git     │
├────────────────────── 状态与后台任务 ──────────────────────┤
```

以下是 GNOME 工作台的起始尺寸，按原生控件、系统字号和可访问性调整；macOS/Windows 分别建立尺寸映射：

- 主标题/全局操作区约 44–48 px；上下文工具条 32–36 px；状态栏 24 px。
- 活动栏 48 px；左侧导航默认 240 px，可在 200–360 px 拖动。
- 右检查器默认 300 px，可在 280–420 px 拖动；需要时展开，不永久挤占源码。
- 底部工具区默认折叠；展开约 220–300 px，可最大化。
- 中间源码/图谱分屏默认 55:45，可拖动；源码建议最小 440 px，图谱最小 360 px。
- 1600 px 可展开右检查器；1440 px 下优先折叠检查器；1280 px 下使用源码/图谱切换标签，允许用户手动分屏。
- 小窗口中隐藏次要工具栏文字，通过 tooltip/溢出菜单保持能力；不要等比例缩小字体。

模式选择为“阅读 / 开发 / 深度分析”，控制后台服务与能力启用。布局选择为“源码 / 分屏 / 图谱”，二者独立，切换模式不强制打乱用户面板位置。

## 4. 视觉系统与设计 token

### 4.1 色彩

**默认实时跟随系统，浅色与深色同等交付；原稿近黑/深蓝黑背景过深，需要提亮，不作为实现标准。**下表是代码/图谱与产品语义的起始 token；shell 控件优先使用平台主题与语义颜色，不能用整套固定色值覆盖 libadwaita/AppKit/WinUI。平台 accent 与产品图谱强调色分开映射，最终验证对比度：

| Token | 暗色建议 | 亮色建议 | 用途 |
|---|---|---|---|
| bg.canvas | #25272B | #FAFAFB | 工作台背景 |
| bg.surface | #2C2E33 | #FFFFFF | 面板与节点 |
| bg.raised | #36383E | #EEF1F5 | 弹层与选中区域 |
| border.subtle | #303B4C | #D4DCE6 | 分隔、边框 |
| text.primary | #E7EDF6 | #182334 | 主文本 |
| text.secondary | #A8B5C8 | #4D5F76 | 次级文本 |
| accent.primary | #63CDBD | #0C6D63 | 主操作、当前焦点 |
| accent.on-primary | #102322 | #FFFFFF | 实色主操作按钮上的文字 |
| status.success | #7CCF9A | #276D3C | 完成/通过 |
| status.warning | #F2C46D | #8A5700 | 候选/不完整提示 |
| status.error | #F18F93 | #B53C49 | 失败/违规 |
| status.info | #8FB8F8 | #2D60A3 | 提示/可导航信息 |

普通文字目标对比度至少 4.5:1，重要控件边界、焦点与图形至少 3:1；以实际相邻颜色验证。`border.subtle` 仅用于装饰分隔，交互边界与焦点使用对比更强的专用 token。不可用浅色小字、颜色或透明度单独传达关键状态。

语言只用小图标/短标签区分，例如 PY、C++、RS、JAVA。节点大面积颜色表达选中/风险等核心状态，避免语言色与关系状态争抢注意力。

### 4.2 字体与密度

- UI 使用平台系统字体与受支持的字号设置，中文 fallback 为思源黑体等可用字体；不要求三个平台使用同一个字体文件。
- 代码默认 JetBrains Mono 或用户等宽字体，关闭/开启连字均可预览。
- 常规 UI 13 px；正文/关键字段 14 px；代码 14 px、行高 21 px；辅助信息 12 px。
- 不把 10 px 的细小文字用作主要信息承载；整体字号可独立缩放。
- 默认紧凑密度，列表行高约 28 px；舒适密度约 34 px。
- 4 px 基础间距；主要间距 8/12/16/24 px；小控件圆角 4 px、面板 6–8 px。
- 细分隔线、克制阴影；面板标题与工具条不使用大面积卡片包装。

### 4.3 图标与动效

- 统一 16/20 px 线性图标，选中与禁用状态完整。
- hover/focus/展开过渡约 100–160 ms；布局变化 150–220 ms，支持关闭动效。
- 索引状态用任务条或状态图标；静止界面不持续旋转、闪动或流动。
- 不使用大面积毛玻璃、霓虹连线、发光节点、装饰性仪表盘和营销式大标题。

## 5. 核心页面要点

### 01 阅读工作台

- 左侧：项目树/符号树标签；五个仓库各有语言与状态；支持只显示活动项目。
- 中间：真实代码行号、面包屑、折叠、当前函数范围；源码作为视觉主角。
- 当前符号信息条：`evaluate(Order) → Decision`、所属项目、引用/调用概览、分析状态。
- 上下文预览可固定在侧面，显示定义片段与“打开定义”，不强制新增标签。
- 关系概览显示调用方/被调用方的少量首项，有“查看调用图”和候选数量。
- 阅读历史/书签/注释为可切换导航；底部工具区收起。
- 展示光标追踪与“固定当前符号”两种状态。

### 02 调用图工作台

- 源码在左、图在右；图可最大化。
- 图工具条：调用方/被调用方/双向、深度、关系类型、项目范围、证据筛选、快照、适应视口。
- 根符号明显，展开点靠近节点端口；显示“+38 个调用方”等受限展开入口。
- 支持按函数/文件/模块/项目聚合，显示递归组。
- 选中边时打开右侧证据；选中节点同步源码定位但不替换固定根。
- 画布底部显示“12 个节点 · 17 条关系 · 2 个候选调用点”，明确是当前视图统计。
- 超过预算时展示“当前展示前 300 个节点 · 调整过滤/继续加载”，不能只把节点消失。

### 03 函数控制流

- 源码与流程图同屏，选中分支双向高亮对应行。
- 支持“阅读流程 / 基础块 CFG”切换；显示函数名、语言、分析配置。
- 节点覆盖入口、条件、动作、循环、异常出口、返回；边有 True/False/异常标签。
- 示例包含 `if`、early return、loop、异常/finally；不要只做三张无语义矩形卡片。
- 可切换异常边、折叠循环；简化节点提示包含的源码范围并可展开。
- 若包含 async，挂起/恢复点有单独标记；路径高亮文案为“控制流可达路径”。

### 04 跨项目系统地图

- 层级切换：系统 → 服务/项目 → 包/模块 → 符号。
- 工作空间 `Orion Commerce`，项目边界清楚，不用一大团函数节点充当架构。
- 契约节点位于调用者与服务实现之间，展示 `gRPC`；PyO3 与 C ABI 边有简洁类型标签。
- 顶部选择部署环境/快照组合；多个实现显示候选组。
- 支持项目/语言/契约/关系过滤、搜索节点、聚合计数、固定布局与保存视图。
- 右检查器显示组件属性、项目列表、主要入口、依赖概览和不完整边界。
- 提供“缺少 staging 部署映射”的实际状态设计，用户可仍然浏览契约。

### 05 关系证据检查器

- 适用于 calls、gRPC、FFI、候选分派等多类边，使用同一组件。
- 首屏顺序：关系概述 → 解析状态 → 双端实体 → 证据 → 代码位置 → 配置/快照 → 限制。
- 证据包含小型源码片段、契约定位、注册/导出配置、分析器/规则版本。
- 按钮：“打开调用点”“打开目标”“查看所有候选”“复制关系链接”。
- 候选示例：`dyn RiskPolicy` 下 3 个实现，说明候选来源；不要显示未经校准的概率。
- 人工映射显示作者/说明/版本；运行时观测显示环境/时间/trace；二者不包装成编译器结论。
- 过期证据显示“源码已变化，当前证据来自上一快照”，提供刷新入口。

### 06 导入与分析状态

- 起始页提供打开目录、添加多个项目、打开工作空间、最近工程。
- 导入后先展示识别到的项目、语言、构建工具与已有环境，用户可直接开始阅读。
- 工程状态项：可用、正在分析、缺环境、被跳过、失败；每项有原因与可操作入口。
- 示例：`pricing-core 缺少 compile_commands.json`；说明当前仍支持搜索与语法结构。
- 首次需要运行构建脚本时展示清楚的执行范围与工程信任入口；不在每次点击图谱时弹窗。
- 任务进度分阶段显示“扫描/语义/桥接/发布”，未知总量时用阶段状态，不伪造精确百分比。

### 07 资源与后台任务

- 入口位于状态栏：“阅读 · 428 MiB · 后台已暂停”，点击展开轻量面板。
- 概览：当前模式、应用受管进程总内存、CPU、缓存、GPU 后端、当前任务。
- 进程/服务列表：core、活动语言服务、分析 worker；每项有用途、资源与停止/休眠入口。
- 预算滑块或预设：省电/均衡/高性能；高级设置显示内存/并发/缓存限额。
- 操作：“暂停后台分析”“仅活动项目”“清理缓存”“查看详细诊断”。
- 超预算提示说明被暂停任务与当前仍可用能力；不可为了资源提示遮挡编辑器。
- 提供图形兼容模式：当前后端、软件模式说明、恢复默认；不需要用户理解底层 API 才能使用。

### 08 搜索与命令

- 统一浮层入口，支持文件、符号、全文、命令的明确类型切换/前缀。
- 结果显示名称、项目、路径、语言、签名；同名符号不能只靠文件名区分。
- 右侧或底部预览代码，支持方向键浏览、Enter 打开、修饰键旁开。
- 全文结果可在独立面板中查看；替换必须先展示范围、命中数与 diff 预览。
- 零结果区分“当前过滤无结果”“索引未完成”“该分析能力不可用”。

### 09 开发与调试

- 沿用主工作台，按需打开终端、测试、问题、输出和 Git。
- 顶部或上下文栏有运行配置、构建、测试、运行/调试、停止。
- 调试状态突出当前执行行；侧栏展示线程/调用栈/变量，底部调试控制台。
- 静态调用图与运行时调用栈使用不同标题与图例，不因调试开启而混为一张确定调用图。
- Git diff/重命名预览保留仓库身份；跨仓库变更按仓库分组。

### 10 变更影响

- 顶部显示变更范围、基线快照与当前工作区，可选一个符号或提交 diff。
- 结果分直接依赖、潜在传递影响、契约风险、建议测试；显示各自含义。
- 中间为选中变更到消费者的解释路径，旁边是可排序的受影响实体表。
- 路径中的未知/候选和边界限制可见；文案使用“潜在影响”，不用“完全证明安全”。
- 操作：打开路径、检查契约、运行选中测试、导出报告。

### 11 架构规则与 DSM

- 左侧规则/组件列表，中间依赖矩阵或架构图，右侧违规证据。
- DSM 支持行列聚合、对角线标识、悬停行列高亮、单元格详情和循环区块。
- 违规卡片只显示必要信息：规则名、源/目标、确定/候选、位置、状态。
- 示例规则：`domain → adapters 禁止依赖`、`项目依赖不可循环`。
- 支持基线、豁免理由/到期与仅显示新增违规；编辑规则有预览与校验。

### 12 快照与阅读路径

- 对比页：旧/新快照选择器、新增/移除/变化关系、变体一致性提示。
- 同名但配置不同的快照需显示差异，不能让数字变化看起来全是代码变化。
- 阅读路径：步骤列表 + 当前代码/图视图，步骤含项目、符号、边界与注释。
- 保存入口明确区分“跟随当前工作区”和“固定快照”；过期步骤可修复或查看旧版本。

## 6. 图谱视觉语法

图谱设计必须有稳定图例；节点形态、边样式与状态分开编码。

### 6.1 节点

| 类型 | 视觉要点 |
|---|---|
| 函数/方法 | 紧凑圆角矩形：名称、语言徽标、项目短名；签名按缩放级别显示 |
| 类/类型 | 类型图标或标题栏；必要时展开成员 |
| 模块/项目 | 分组容器，可折叠；聚合计数显示单位 |
| 契约 | 六边形或有专属图标的窄卡片：服务/操作名 + gRPC/HTTP/Topic |
| 外部实体 | 轮廓卡 + 外部箭头图标，标注包版本与无源码 |
| 未解析边界 | 带问号图标的端点，显示原因与修复入口 |
| SCC 递归组 | 可展开组合节点，有循环标记和成员数 |

选中使用清晰边框与焦点环；搜索命中、悬停、固定根、违规和键盘焦点要有可组合状态。节点完整名称可 tooltip/检查器查看，默认截断不能隐藏全部关键标识。

### 6.2 边

| 语义维度 | 视觉编码 |
|---|---|
| 确定解析 | 实线箭头 |
| 候选目标 | 虚线箭头 + 候选标记/计数 |
| 未解析目标 | 连到问号端点，短点线，显示原因 |
| calls/import/type_ref | 边标签或过滤器图例标识种类 |
| RPC/FFI | 显式 `gRPC` / `PyO3` / `C ABI` 标签与边界端口 |
| 来源为规则/人工 | 小型证据徽标，选中后展开 |
| 运行时观测 | 独立叠加层，有 trace 标识与时间/环境 |
| 过期事实 | 时钟标记与“旧快照”说明，不只降低透明度 |

箭头方向统一表达源依赖目标/调用方到被调用方；需要反向探索时改变展开方向，不反转边的语义。边上的数量需标明“调用点/符号对/操作/运行时次数”，不能只放一个含糊数字。

### 6.3 缩放与可读性

- 远景只看项目、模块和聚合关系；中景显示函数名；近景显示签名与位置。
- 悬停边强调对应路径，降低无关信息的视觉权重，保证关键文字可读。
- 默认无持续物理弹动；增量展开尽量保持已有节点位置。
- 导航工具含缩放、适应视口、回到根、布局、图例；小地图只在大图时出现。
- 图谱必须有等价树/表视图，支持键盘与屏幕阅读器。

## 7. 交互规则与状态矩阵

### 7.1 一致交互

- Hover：轻量预览；单击：选中；双击/Enter：进入源码或下钻。
- Space/拖动空白：平移；触控板双指：平移；缩放遵循平台约定并允许配置。
- 右键菜单与命令面板可访问同一核心动作。
- Esc：关闭预览/弹层或清除临时选择，不能取消用户未保存修改。
- 后退/前进恢复源码选区、根符号、图视口与过滤状态。
- 图可固定，不随每次光标移动重新布局；“跟随光标”是可见开关。
- 面板可隐藏、停靠、恢复默认布局；用户布局跨重启保存。

### 7.2 必须补齐的状态

| 场景 | 应展示的内容 | 主要动作 |
|---|---|---|
| 未打开工程 | 最近工程、打开/添加入口 | 打开目录 |
| 首次扫描 | 阶段、已发现文件、可用能力 | 开始阅读/暂停 |
| 语义未完成 | 已有结果、当前缺口 | 查看进度 |
| 缺少工具链 | 具体缺项、受影响项目 | 选择环境/导入配置 |
| 查询无关系 | 范围、过滤与已分析程度 | 调整范围 |
| 多目标候选 | 数量与依据 | 展开候选 |
| 图超预算 | 当前数量与截断说明 | 聚合/继续加载 |
| 源码已改 | overlay/旧快照状态 | 切换/刷新 |
| 分析器失败 | 最后可用快照与错误摘要 | 重试/诊断 |
| 内存预算到达 | 暂停对象和剩余可用能力 | 缩小范围/调预算 |
| 离线/缺工具包 | 本地可用能力、缺失功能 | 导入离线包 |
| GPU 兼容模式 | 当前状态、体验变化 | 打开兼容设置 |
| 快照不匹配 | 项目/变体/契约版本差异 | 选择兼容组合 |

异常提示优先使用就近状态、侧面详情与可恢复操作。只有确需决策的操作使用模态对话框。

```python
async def assess(order: Order) -> Decision:
    if not order.items:
        return Decision.reject("empty order")

        score = risk_bridge.calculate(normalized)
        return Decision.approve() if score < 0.7 else Decision.review()
    except PricingUnavailable:
        return Decision.review(reason="pricing unavailable")
```

## 13. 双维热度与缓存设置补充提示词

以下可直接交给 Claude Design / Google Stitch，仍以 macOS 原生设计为首轮：

> 为 Symweft 补充“热点与阅读关注”表和资源设置。文件、符号分别有两列独立指标：结构热度、阅读关注；支持各自排序，不合并成一个不透明总分。结构项展示静态调用位置/独立调用者/跨文件来源及证据精度；A1 阶段只展示“语法名字候选”，明确歧义与 unresolved，不能标成准确被调用次数。阅读项展示有效前台时间、主动打开次数、最近访问和 7 天衰减关注，0 与 unknown 区分。文件、符号、图节点可相互定位；图配色可切换结构/阅读，不同时混用两种颜色含义。无真实历史时显示空状态，不填演示数值为真实数据。支持 JSON/CSV 导出、停止采集、清空当前项目记录。
>
> 资源设置提供自动/手动/关闭附加热缓存、最大 MiB、预读开关；同时展示配置上限、实际生效预算、事实池使用、元数据、SQLite 页缓存和独立进程 RSS，不将它们混称一个值。内存压力时显示缩减原因，预读暂停状态和恢复过程；保留当前源码阅读。高级页提供命中、淘汰、预读被使用/未使用、额外读取及等待延迟，普通阅读页面只留克制状态，不暴露存储实现细节。手动上限遇严重压力也可能紧急收缩，界面必须解释实际值。
>
> 浅色/深色实时跟随系统；沿用原生 macOS Settings、toolbar、sidebar、inspector 与语义色，提亮原稿过深背景。GNOME 后续独立使用 libadwaita 偏好与状态习惯，Windows 后续独立映射，不把 Linux header bar 位置复制到 macOS。

当前实现只有缓存设置/采集开关/清空和数据 API/导出；完整热点表与图谱配色为待设计功能。
