## 2026-10-18：macOS 开发起点与主题修订

用户确认的最新要求：

1. 软件名为 **Symweft（织源）**，项目目录为 `symweft`。
2. 由于当前开发机为 macOS，**先搭建并运行 macOS 原生前端**；共享 Rust 核心保持跨平台。Linux/GNOME 仍是重要目标，后续接入，Windows 更后，不要求同步交付。
3. **主题默认跟随系统，并在系统外观改变时实时更新**。同时提供“跟随系统 / 浅色 / 深色”选择，默认是跟随系统。
4. **现有设计稿颜色太深**。其页面结构、信息与交互可参考，深蓝黑固定背景不作为实现标准。优先使用 macOS 语义颜色和原生材质；自绘代码区的深色背景适度提亮，浅色模式完整可用。
5. 系统主题需要覆盖窗口、侧栏、编辑器、检查器、弹层与后续图谱，不只切换最外层背景；字体、焦点、选择与诊断对比度一并验证。

### 当前搭建范围

- Cargo workspace 与独立 Rust core 进程，建立版本化 JSON Lines 本地 stdio 协议。
- Swift Package macOS 应用，可通过 Command Line Tools 构建与打包，不依赖第三方 Swift 包。
- 原生窗口/菜单/工具栏、工作空间目录选择、真实文件树、AppKit 源码阅读区、文件元信息与状态栏。
- 主题选择持久化；系统模式不设置固定 `NSAppearance`；代码区使用随 effective appearance 更新的动态颜色。
- 本轮是可运行的只读阅读骨架，不声称已实现语义索引、调用图、代码编辑保存或调试。
- ui_desgin 是用户提供的 Stitch 设计初稿，保留 HTML/PNG；仅在设计说明中追加最新约束，不将初稿作为 WebView 产品界面。

### 实现边界

- Rust 负责工作空间扫描、语言识别、受限文件读取与协议；Swift 负责原生交互和呈现。
- 仅扫描文件，不运行构建脚本或导入用户模块；文件数、读取大小、排除目录与符号链接策略有显式限制。
- 版本化协议与 UI 分开，Linux 后续可以直接复用 core。
- 首期协议使用 JSON Lines 便于联调；大批量语义事实再升级流式分页/二进制批次，不把当前小型协议误称为最终分析引擎。

### 后续顺序

此处原定顺序已由下方“分析引擎优先”修订，后续以分析闭环为主线。

### 本轮验证

- SwiftUI/AppKit 应用与 Rust core 已在本机编译、打包并通过本地开发签名。
- Rust 的 5 个测试及 clippy 静态检查通过。
- 不依赖完整 Xcode/XCTest 的 macOS 检查已验证文件树身份、动态配色、真实 Rust/Swift 握手/扫描/中文读取及协议错误恢复。
- 浅色和深色启动已验证；新版 AppKit 行号栏覆盖正文首列的问题已修复。
- 本机环境为 macOS 26.6.2 / Apple Silicon，Swift 6.3.3、Rust 1.99.0；声明的最低系统/工具链仍需在相应环境单独验证。

## 2026-10-18：分析引擎优先与首个交互分析闭环

用户进一步确认：**最重要的是代码分析，尽可能降低资源和提高速度，并在 IDE 中即时获取函数调用与代码关系。** 因此不再先扩充通用 IDE 外壳。

### 本轮实现

- 新增共享 Rust crate：symweft-analysis。嵌入 core，不新增额外常驻进程；语法分析不启动语言服务器、JVM 或编译器。
- 固定 Tree-sitter 与 Python、C、C++、Rust、Java grammar 版本，生成常见定义、作用域和显式调用点。
- 旧树增量解析、无变化复用、单调修订、UTF-8 编辑校验、失败原子性、文档/源码/估算内存/事实数量/时间预算。
- core 新增文档打开/内存编辑/关闭、快照查询、光标上下文与缓存统计接口；请求上限调整为 4 MiB，以容纳受限文档的转义文本编辑。
- macOS 增加文件大纲、按光标函数筛选调用点、点击源码定位和实际引擎耗时。采用行锚点转换 UTF-8 与 AppKit UTF-16，保持系统主题。
- 新增多语言、增量与完整解析一致性、Unicode、缓存和协议端到端检查；可重复发布版微基准随源码保存。

### 已知边界

当前为 A1 语法事实，调用目标仍 unresolved；不按同名猜测真实调用边。每次成功增量解析后仍全文件重提取事实；当前服务为顺序请求处理。macOS 仍只读，内存编辑接口尚未接到用户输入。工作空间语义索引、持久化、跨项目、CFG 与图谱均未完成。

### 修订后的实施顺序

1. 当前文档分析、光标查询、缓存预算与性能基线。
2. 文档缓冲区与编辑事务、作用域增量提取、并发快照、优先级/取消调度。
3. 首个语言的准确语义定义/引用/出入调用闭环，覆盖未保存内容。
4. 工作空间持久化关系、依赖失效、批量索引与低资源后台运行。
5. 跨项目证据连接、真实图谱与架构分析，逐步补齐 IDE。Linux/GNOME 在核心协议稳定后即可接入，不要求等待所有高级分析完成。

详见 [分析引擎与实时关系设计](05-分析引擎与实时关系设计.md)。性能目标与本机实测严格分开。

- macOS 检查验证真实 grammar 事实、内存增量编辑、旧修订拒绝、上下文查询、磁盘内容未被修改，以及 UTF-8/UTF-16 的 emoji/组合字符/CRLF 转换。

## 2026-10-18：QEMU、存储评估与缓存落地

- 新增 symweft-index：SQLite WAL、SWF1 二进制事实块、BLAKE3 输入/载荷校验、事务文件替换及二级查询；core 的 document.open 跨重启直接恢复，无 AST。未保存编辑只在内存，首次编辑按需建树。
- 独立有界存储线程，连续写合并，事实写队列 16 MiB 上限；flush 和状态报告错误。新增显式流式 bulk 命令，不把全量工作塞入交互循环。
- 对同份 QEMU 事实实际比较 SQLite raw/indexed、append pack、SQLite+segment 混合；当前选完整 SQLite，实验后端保留，未宣传原型具备生产 GC/跨平台恢复。
- 热事实按字节计费，最多 4,096 项，采样频率/字节淘汰；动态压力预算、手动上限、关闭、受限 include 预读。macOS 设置跟随原生系统主题，接入内存压力与保守的前台阅读采样，可关闭/清空关注。
- 结构语法候选和真实阅读关注分开保存/查询/导出。全库导出 81,174 符号、6,723 文件；本次关注全为 0，synthetic replay 不写用户记录。修正了 QEMU 条件作用域下同名父作用域引起的稳定身份冲突。
- QEMU：完整生产命令 15.47 s（内部 14.740 s），核心峰值 RSS 35.94 MiB，索引 66.63 MiB；未变化再次检查 1.29 s。Worker 恢复 1,000 文件 p95 1.354 ms，解析 0，不含 UI/stdio。完整方法和取舍见 [报告](09-QEMU性能与存储选型报告.md)。
- Rust 21 项测试和 clippy 通过；Swift foundation 验证真实协议重启恢复、未保存隔离、手动预算和压力。Swift 发布构建明确文件树递归恢复函数的 MainActor 隔离，并避免短路闭包引起的隔离诊断；原生双主题 QEMU 检查修正了函数定位后行首被横向偏移的问题。

边界：以上为 A1；3,044 QEMU 文件带语法错误标志，宏/构建上下文与语义调用未解决。还没有真实用户编辑保存、文件监听、完整热度 UI、准确跨项目语义、CFG 或图谱。超大规模设计仍需 10 倍/100 倍样本、长期运行和故障测试，不能将第一轮 QEMU 结果视为所有规模承诺。

## 2026-10-18：原生监听、实时更新与读取优化

- 增加 notify 原生监听、有界路径合并、查询指纹 epoch 和结构 publish_epoch；已知输入修改按反向依赖更新，新头文件等搜索结构变化保守失效已记录范围。索引缓存和读取事件过滤，嵌套监听根去重。
- 自动队列静默 350 ms、单工作进程、活动文件优先，最多 256 个已知单元；超限全部过期并要求显式刷新，不自动扩大到编译数据库全量。纯 serve 客户端需要持续语义请求来推进维护，macOS 每 750 ms 轮询。
- 查询连接复用；新增两个各最多估计 1 MiB 的指纹池，按文件属性和短时限复用摘要，64 KiB 流式 hash。保留严格内容模式，监听错误降级；这不是常驻语义事实热池或完整文件系统快照。
- dirty 缓冲区阻止自动磁盘事实发布，释放后继续待更新任务；取消、恢复和内存压力状态分别处理。切换监听设置先消费旧队列，首次失败无依赖快照时也按主文件变化恢复；配置变化且存在 dirty 文档时取消和进度仍可用。
- 原生面板增加自动更新、严格校验及刷新已索引范围；外部原子保存后自动重载只读源码并更新绑定关系，浅色/深色均实测 first → second。未来可编辑模式需要冲突处理，不能照搬只读自动重载。
