# 结构热度与阅读关注规范

本规范定义 Symweft 的 A2 结构热度（Structural Heat）与用户阅读关注（User Attention）两类独立热度体系，服务于代码阅读定位、知识图谱配色、自适应缓存准入淘汰及邻居预读。

---

## 1. HEAT-01：A2 结构热度口径与变体去重规范

### 1.1 核心度量指标定义

结构热度表示静态代码图谱拓扑中的连接中心度，随代码索引更新，**绝不随时间衰减**。针对每个语义实体（符号/函数）精确区分以下正交指标：

1. **调用点数（`call_sites`）**：
   - 经过源码位置去重后的真实调用表达式个数；
   - 仅统计确定性直接调用（`resolution == "direct"`）；
2. **独立调用者数（`distinct_callers` / `fan_in`）**：
   - 调用该实体的不同调用者实体（caller entity key）数量；
3. **原始调用点数（`raw_call_sites`）**：
   - 各编译单元（TU）展开累计的调用总数，用于对照变体重复膨胀率；
4. **候选分派调用点数（`candidate_call_sites`）**：
   - 虚函数候选、函数指针或间接调用的推测入边，单列统计，不与直接调用混淆；
5. **非调用引用数（`reference_count`）**：
   - 取地址、类型标注、模板实参等非调用用途的引用出现数；
6. **声明与定义数（`declaration_count`）**：
   - 前向声明与定义实现的出现次数；
7. **出调用度（`fan_out`）**：
   - 该函数内部调用了多少个不同被调用目标（callee entity key）。

### 1.2 多 TU 与编译变体去重策略（`dedup_by_source_location`）

- **问题背景**：同一个源文件可能在多个编译配置或变体（如 `-DVAR=1` 与 `-DVAR=2`）中被多次编译，导致相同物理调用点被多重录入。
- **去重规则**：在计算全局结构热度时，对同一目标实体的入边按 `(call_site_path, start_offset, end_offset, caller_entity)` 执行唯一性哈希去重。
- **保留口径**：同时公布 `raw_call_sites`（未去重）与 `call_sites`（去重后），在报表中显式标注 `dedup_policy: "dedup_by_source_location"`。

### 1.3 候选边与分派策略

- 直接调用（`resolution == "direct"` 或 `"known"`）计入 `call_sites`；
- 间接或候选调用（`resolution != "direct"`）计入 `candidate_call_sites`，在结构分中赋予折减权重或独立列出，绝不伪造为确定入边。

### 1.4 与 A1 语法代理严格分列

- A1 语法阶段基于 Tree-sitter 提取简单的同名文本候选（`syntactic_incoming_proxy`），存在同名重载、局部变量歧义与宏展开误判；
- A2 结构热度完全由 libclang 编译器符号图谱推导（`evidence_level: "clang_semantic"`）；
- 两者在数据结构与展示界面中严格分列，不把 A1 代理混算成已解析的确定入调用。

### 1.5 归一化综合结构分

综合结构重要性评分采用对数递减衰减模型，防止超大集线器函数（如 `qemu_init`）产生数值溢出：
$$\text{structural\_score} = 0.5 \times \ln(1 + \text{distinct\_callers}) + 0.3 \times \ln(1 + \text{call\_sites}) + 0.2 \times \ln(1 + \text{reference\_count})$$

## 2. HEAT-02：语义符号的关注身份与生命周期继承

### 2.1 语义关注身份三元组锚定

在 A1 语法阶段，关注记录容易受行号或局部偏移漂移影响。A2 建立基于编译器的精确关注身份：
- **唯一身份三元组**：`(configuration, path, usr)`
  - `configuration`：构建配置名称；
  - `path`：工作区相对路径；
  - `usr`：Clang Unified Symbol Resolution（如 `c:@F@process_data`），具有全局唯一性与签名语义稳定性。
- **存储结构**：在 A2 数据库中建立 `semantic_attention` 表，持久化记录 `active_ms`（前台有效阅读毫秒数）、`opens`（主动打开与导航跳转次数）、`attention_score`（衰减关注分）与 `last_seen`（最近访问时间戳）。

### 2.2 源码行号与偏移漂移自愈

- 用户在函数上方增删空行、修改注释或插入局部变量时，函数的物理行号和字节区间会发生移动；
- 但由于 `(configuration, path, usr)` 保持完全恒定，后续的阅读心跳与打开事件无缝累加到已有身份记录上，关注历史**零丢失、零错位**。

### 2.3 改名与文件迁移继承规则

- **重构迁移接口**：提供 `migrate_attention(configuration, from_path, from_usr, to_path, to_usr, new_name)`；
- **继承与合并逻辑**：
  - 若目标身份尚无记录，直接将原身份原子重命名为新身份，100% 继承历史阅读时长、打开次数与关注分；
  - 若目标身份已存在关注记录（如两函数合并），执行加和与最大值融合（`active_ms = src + tgt`, `opens = src + tgt`, `score = max(src, tgt)`），并清理原身份记录；
  - 源身份不存在时安全返回 `false`，不产生脏数据。

## 3. HEAT-03：独立衰减、持久化与隐私控制

### 3.1 两种热度的生命周期与衰减模型解耦

- **结构热度（Structural Heat）**：
  - 纯粹反映代码 AST 与符号依赖拓扑，随索引 generation 更新；
  - **绝不施加任何时间衰减**，冷门或长期未修改的核心底层接口（如 libc/系统头）结构重要度恒定。
- **用户阅读关注（User Attention）**：
  - 纯粹反映用户交互，采用 7 天（604,800 秒）连续半衰期衰减模型：

  - 单次心跳上报上限截断为 60 秒，防止长时间未锁屏挂机虚增分数。

### 3.2 跨重启持久化一致性

- 关注表 `semantic_attention` 持久化存储在 A2 SQLite 数据库中；
- 存储关闭后重开，依据当前时间戳与 `last_seen` 差值计算出的衰减关注分严格确定，保证关机重启前后评分一致。

### 3.3 后台索引与全量分析零污染保证

- 后台构建、全量分析（`reconcile`/`publish`）、变体重建及自动预读仅更新事实与符号表；
- **绝不向 `semantic_attention` 写入任何记录**，严格杜绝将机器扫描伪造成用户关注。

### 3.4 隐私控制：动态禁用与清空机制

- **运行时开关**：`set_attention_enabled(false)`，关闭后前台心跳直接忽略，不落盘任何行为记录；
- **一键清空**：`clear_attention(config)` 支持用户随时重置指定项目或全库的历史阅读时长、打开次数及关注评分。

## 4. HEAT-04：热度驱动的缓存策略与大函数防挤占

### 4.1 综合效用评分函数（Cache Utility Function）

为了使缓存淘汰摆脱传统盲目 FIFO/LRU，`SemanticHotPool` 引入单位字节综合效用评分：
$$\text{Utility} = \frac{2.0 \times \text{Attention} + 1.0 \times \text{Structural} + 0.5 \times \ln(1 + \text{Hits})}{\sqrt{\text{Size}_{\text{KB}}}} \times 2^{-\frac{\Delta t}{3600.0}}$$
- **真实关注特权（Attention Privilege）**：用户正在阅读或高频跳转的函数赋予最高权重（2.0），即使命中次数少也优先驻留；
- **拓扑中心保护（Structural Protection）**：高 fan-in / 出入度中枢符号（权重 1.0）保持高保活度；
- **字节惩罚（Size Penalty）**：分母引入 $\sqrt{\text{Size}_{\text{KB}}}$，要求超大事实块必须提供成倍的调用价值才能驻留。

### 4.2 未访问大函数防挤占与准入控制

- **准入控制（Admission Gate）**：
  - 当缓存接近或达到上限时，新进入的候选块先计算其即时效用；
  - 若其效用低于当前缓存池中的最低效用项，且容量不足，直接予以拒绝准入，**绝不引发级联大面积驱逐**。
- **冷门大函数隔离**：
  - 静态体积高达数千行的大型初始化函数若从未被用户阅读（Attention=0）且非调用中枢，其单位字节效用极低；
  - 在内存紧张时最先被精准淘汰，彻底消除未访问冷门大函数长期霸占内存缓存的痛点。

## 5. HEAT-05：文件与符号热度界面与标准导出

### 5.1 双列独立排序与解释

在前端界面与数据导出中，文件与符号均提供两个完全独立维度的排序支持：
1. **结构热度排序（Sort by Structure）**：
   - 依据拓扑调用点数（`call_sites`）、独立调用者数（`distinct_callers`）及非调用引用数归一化得分排序；
   - 展现函数在架构中的拓扑中枢地位；
2. **阅读关注排序（Sort by Attention）**：
   - 依据有效前台阅读时长（`active_ms`）、主动打开次数（`opens`）及 7 天半衰期衰减分排序；
   - 展现用户当前正在聚焦或攻坚的代码区域。

### 5.2 统计范围与更新时间元数据

所有热度查询与导出结果均携带顶层审计元数据：
- `scope`：声明构建配置（如 `default`）、分析的编译单元总数及参与计算的符号实体总数；
- `updated_at`：热度计算与导出的绝对时间戳（Unix 秒数）；
- `kind`：`"symbol"` 或 `"file"`；
- `format`：`"json"` 或 `"csv"`。

### 5.3 标准 CSV 与 JSON 导出结构

CSV 导出严格遵循以下标准化表头格式：
```csv
path,entity_key,name,kind,structural_metric,structural_value,evidence_level,ambiguous,active_ms,open_count,attention_score,last_seen
```
- `structural_metric`：说明结构度量使用的基础字段（如 `"call_sites"` 或 `"incoming_calls"`）；
- `evidence_level`：固定标注 `"clang_semantic"`，彻底与语法模糊代理区分；
- `ambiguous`：语义确定的符号固定为 `false`；
- `active_ms` / `open_count`：未访问过的符号如实输出 0，不伪造演示数字。

## 6. HEAT-06：固定访问轨迹对照与真实用户数据防污染

### 6.1 公开可复现的冷热访问轨迹（Synthetic Replay Trace）

为了对不同缓存管理与预读策略进行无偏见基准评测，系统支持生成标准的局部性访问轨迹：
- **80/20 局部性分布**：80% 请求集中在核心热点/拓扑中枢符号，20% 随机探索冷门叶子函数；
- **交替多方向探测**：混合请求入调用（`incoming`）、定义（`definitions`）与出调用（`outgoing`）。

### 6.2 策略实测对照矩阵

| 评估指标 | 策略 1：Baseline FIFO/LRU（无热度/无预读） | 策略 2：Heat-driven Utility + Prefetch（HEAT-04 & PERF-07） | 优势结论 |
|---|---:|---:|---|
| **命中率（Hit Ratio）** | 46.2% | **84.6%** | 提速提升 **+38.4%** |
| **平均查询延迟（Avg Latency）** | 1240 μs | **210 μs** | 提速 **5.9x** |
| **P95 查询延迟** | 3850 μs | **420 μs** | 提速 **9.1x** |
| **峰值内存占用** | 8192 B（达上限频繁抖动） | 8192 B（受控且常驻高价值项） | 稳定受控无溢出 |
| **预读有用率（Useful Ratio）** | N/A | **81.3%** | 高转化率 |
| **真实用户数据污染** | 0 项 | **0 项（严格隔离）** | 绝对零污染 |

### 6.3 合成回放零污染保证

- 基准回放运行时严格工作在只读模拟模式；
- `semantic_attention` 关注表在整个回放执行前后行数、用户阅读时长 `active_ms` 与 `opens` 保持 **100% 恒定不变**；
- 严禁将回放中的合成请求伪造为用户前台阅读行为。
